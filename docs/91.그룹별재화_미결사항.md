# 91. 그룹별 재화 설정 — 미결 사항 / 결정 필요 사항

> 작성일: 2026-10-15
> 상태: **대부분 결정·구현 (2026-10-23)** → [95.게임진행_설계.md](95.게임진행_설계.md). 4종 고정, 정수·음수 거부, 생산/정정 증감 입력, 팀원 전원 열람·타 팀 불가, 이력은 관리자만, 프레젠테이션은 초기 합계만, 거래는 요청→수락 자동 이체. 아래 표는 당시 기록.
> 관련: [90.개발환경초안.md](90.개발환경초안.md) 3절 "테마 > 재화 표시", 11절 "다음 단계"

## 1. 현재 상태

| 있음 | 없음 |
|---|---|
| 재화 4종의 표시 정의(이모지·색·순서): `client/src/lib/resources.ts`, `ResourceChip.vue`, `ResourceRow.vue` | 수량 저장 테이블 |
| `/group`, `/present` 에 수량 "–" 미리보기 | 관리자 입력/조정 API 와 화면 |
| 이벤트 outbox + Socket.IO (`scope=group` 으로 그룹 전용 전달 가능) | `resource.updated` 이벤트 타입 |
| 그룹 생성/삭제/재배정 (`POST /api/admin/roster`) | 그룹 삭제·재배정 시 재화 처리 규칙 |

재화 종류와 색 순서는 확정: **보석=화이트 💎, 골드=옐로우 🥇, 라이프=블루 💙, 크레딧=레드 🎟️**.

## 2. 구현 시 필요한 구성 (룰과 무관하게 고정 가능)

1. **DB** (`server/migrations/0004_resources.sql`)
   - `group_resources(group_id, kind, amount, updated_at)` — 현재 보유량. `(group_id, kind)` 유니크
   - `resource_ledger(id, group_id, kind, delta, amount_after, reason, created_by, created_at)` — 모든 변동 이력. 실수 복구·사후 검증용
   - `settings` 에 재화별 공개 여부 (`resource.public.<kind>`) 와 숨김 여부 (`resource.hidden.<kind>`)
2. **API**
   - 관리자: `GET /api/admin/resources` (전 그룹), `PUT /api/admin/groups/:id/resources` (절대값), `POST /api/admin/groups/:id/resources/adjust` (증감 + 사유)
   - 참가자: `GET /api/group` 응답에 자기 그룹 재화 포함 (토큰의 groupId 기준, URL 조작 불가)
   - 프레젠테이션: `GET /api/board` — 공개 설정된 재화만
3. **이벤트**: 변경 시 `resource.updated` 를 해당 그룹(`scope=group`)에, 공개 재화면 전체(`scope=all`)에도 발송. 클라이언트는 받으면 재조회
4. **화면**: `/admin` "관리 기능" 카드에 그룹 × 재화 입력 표 + 증감 입력 + 사유, 이력 보기. `/group`, `/present` 의 "–" 를 실제 수량으로 연결

## 3. 결정 필요 사항

괄호 없는 "추천" 은 룰이 없을 때의 기본값. 결정 칸이 비어 있으면 미결.

| # | 항목 | 선택지 | 추천 | 결정 |
|---|---|---|---|---|
| 1 | 재화 종류 | (a) 4종 고정 (b) 관리자가 추가·삭제 | (a) 4종 고정 + 재화별 "숨김" 플래그. 방송처럼 골드가 중간에 등장하는 경우는 숨김 해제로 처리 | |
| 2 | 프레젠테이션 공개 범위 | (a) 그룹별 수량 전부 공개 (b) 전체 합계만 (c) 관리자가 재화별 토글 | (c) 재화별 토글 + 기본 비공개. 방송은 1일차 총량만 공개, 이후 비공개 | |
| 3 | 관리자 입력 방식 | (a) 절대값 덮어쓰기만 (b) 증감만 (c) 둘 다 | (c). 초기 세팅은 절대값, 거래 반영은 증감. 둘 다 이력에 남김 | |
| 4 | 변동 사유 입력 | (a) 필수 (b) 선택 | (b) 선택이되 프리셋 버튼(거래, 전쟁, 생산, 제출, 정정) 제공 | |
| 5 | 음수 허용 | (a) 0 미만 거부 (b) 허용 | (a) 거부. 부족하면 관리자에게 오류 표시 | |
| 6 | 참가자 열람 범위 | (a) 그룹원 전원 (b) 리더만 | (a) 그룹원 전원. 리더 전용 정보는 룰 확정 후 `scope=user` 로 분리 | |
| 7 | 타 그룹 재화 열람 | (a) 불가 (b) 특정 그룹(블랙 역할 등)에 허용 | (a) 불가. 방송의 "정보 조회권" 같은 특권은 룰 확정 후 | |
| 8 | 거래·전쟁 자동 반영 | (a) 수동 조정만 (b) 거래 요청→승인 시 자동 이체 | (a) 수동만. 거래 승인 흐름은 룰 확정 후 별도 설계 | |
| 9 | 그룹 삭제 시 재화 | (a) 소멸 (b) 남은 그룹에 합산 (c) 삭제 거부 | (c) 재화가 0 이 아니면 그룹 수 축소 거부. 진행 중 실수 방지 | |
| 10 | 그룹 수 증가 시 초기값 | (a) 0 (b) 관리자가 지정한 기본값 | (a) 0. 생성 후 관리자가 절대값으로 입력 | |
| 11 | 초기 세팅 입력 | (a) 그룹별 개별 입력 (b) 전 그룹 동일값 일괄 입력 (c) 둘 다 | (c). 일괄 입력 후 개별 수정 | |
| 12 | 단위·소수 | (a) 정수만 (b) 소수 허용 | (a) 정수. 방송 재화도 모두 개수 단위 | |
| 13 | 크레딧 변종 | (a) 단일 (b) 일반/무공해 분리 | (a) 단일. 룰에서 변종이 필요해지면 kind 추가 | |
| 14 | 이력 열람 | (a) 관리자만 (b) 그룹원도 자기 그룹 이력 열람 | (a) 관리자만. 참가자는 현재값 + 변동 알림만 | |
| 15 | 변동 알림 문구 | (a) 수량만 ("보석 +3") (b) 사유 포함 | (a) 수량만. 사유는 관리자 메모 성격 | |

## 4. 룰 확정 후 다시 볼 항목

- 재화별 역할 확정: 방송 기준 보석=상금, 골드=상금 결정, 라이프=생명(매일 제출), 크레딧=기회. 이 게임에서 같은지
- 라운드·일차 개념이 들어오면 "일차별 스냅샷" 테이블 필요 여부 (현재 ledger 로 재구성 가능하지만 조회가 느릴 수 있음)
- 거래 요청/수락 UI 가 생기면 #8 을 (b) 로 전환하고 `trade.*` 이벤트 추가
- 프레젠테이션 현황판 레이아웃 (TV/빔 출력용 큰 글씨, 그룹 컬러)

## 5. 백업·운영 메모 (결정과 무관)

- 재화 변경은 모두 `resource_ledger` 에 남으므로 잘못 입력해도 이력을 보고 정정 가능
- 게임 당일 시작 전·후 `./data/csd.sqlite` 복사 (90 문서 5절)
- 관리자 2명이 동시에 같은 그룹을 수정하면 나중 요청이 이김. 증감 방식(#3)을 쓰면 충돌 영향이 작음
