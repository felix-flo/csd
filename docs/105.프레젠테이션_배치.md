# 105. 프레젠테이션 배치 — 한 화면에 팀 현황까지

> 작성일: 2026-10-31
> 상태: **구현 완료 (2026-10-31)**. 측정값은 본문 §검증
> 관련: [104.가시성_기준.md](104.가시성_기준.md), [103.운영테스트_2차_수정.md](103.운영테스트_2차_수정.md) §12 §14

## 1. 문제

docs/104 로 글자를 키운 뒤 재 보니, 게임 중 프레젠테이션은 팀 현황까지 보는 데 세로 1,325px 이 필요했다 (팀당 2명 기준, 1920 폭).
프로젝터로 흔한 1080p(1,080px) 에도 안 들어가고 720p 면 타이머·안건 카드까지만 보였다. 원인은 셋.

- 접속 QR 카드가 443px 로 가장 컸다. 시작 후에는 모두 접속해 있어 큰 QR 이 필요 없다.
- 초기 재화 카드(277px)는 한 번 보면 끝인 정보인데 큰 칩이 두 줄로 접혔다.
- 제목 상단바와 단계 표시줄이 두 줄, 타이머와 안건 카드가 세로로 쌓여 폴드 위 584px 을 운영 정보만 썼다. 가장 중요한 팀 현황이 세 번째 화면에 있었다.

## 2. 새 배치 (게임 시작 후)

```
1줄  제목 (왼쪽) · 연결/소리/룰/로그아웃 (작게)   │ 1라운드 / 총 3라운드  리더 협의 중  [단계 칩]
2줄  ⏱ 남은 시간 03:47 (1/3)                      │ 🗣️ 리더 협의 안건 — 원조 · 전쟁 허용/제재 → 결과 (2/3)
3줄  팀 현황 4열: 팀 이름 n/N · 리더 · 팀원 명단                    (남는 높이를 모두 차지)
4줄  현황판 (골드 누적 · 전쟁)  │ 초기 재화 한 줄  │ QR 96px + 주소  │ 최근 알림 3건 (한 줄씩)
```

- 2줄은 타이머나 안건이 있을 때만. 하나만 있으면 전체 폭.
- 전쟁 중 표시줄(`.war-bar`)은 1줄 아래 전체 폭.
- 최종장 결과판·완료 배너는 1줄 아래 전체 폭 (기존 위치).
- 시작 전(설정·준비)은 그대로: 입장 현황(또는 초기 재화) 크게 + QR 크게.
- 토스트는 프레젠테이션에서 **오른쪽 아래**에 쌓인다 (제목·단계·타이머를 가리지 않게).

### 폭 1400px 이하 (720p 급)

글자를 한 단계 줄이고 4줄은 현황판 + 초기 재화만 (QR·알림 기록 숨김). 단계 표시줄의 "/ 총 N라운드" 생략.

### 구현

- `PresentView.vue`: `.page.present` 를 `min-height: 100vh` 세로 flex 로, 팀 현황 카드가 `flex: 1` 로 남는 높이를 차지. `TopBar` 가 내는 `.topbar` 와 `.phase-bar` 는 `.head` flex 로 한 줄.
- `EventFeed` 에 `limit` prop (최신 N건, 펼치기 없음). 프레젠테이션 4줄에서 `plain :limit="3"`, 한 건을 한 줄(뱃지 · 시각 · 메시지…)로.
- `ToastHost`: `.toast-host.large` 를 `bottom: 16px`.

## 3. 검증 (2026-10-31, 스크래치 DB, 리더 협의 단계)

| 화면 | 팀당 2명 | 팀당 6명 | 비고 |
|---|---|---|---|
| 1920 폭 (1080p) | 891px | 903px 이내 (스크롤 없음) | 브라우저 창 903px 에서도 스크롤 없음. 전체 화면이면 여유 |
| 1280 폭 (720p) | 569px | 695px | 720 안에 들어감. 1줄이 두 줄로 접혀 97px |

블록 높이 (1920 폭): 1줄 68 · 2줄 152 · 팀 현황 2명 356~6명 464 · 4줄 166.

`npm run typecheck`, `npm run build -w client` 통과.

## 4. 운영 메모

- 프레젠테이션은 **F11 전체 화면** 또는 `chrome --kiosk` 로 띄운다. 탭·주소창이 150~180px 을 먹는다.
- 팀원이 7명 이상이거나 720p 에서 팀 이름이 길면 팀 현황이 넘칠 수 있다. 그때는 `.roster-team ul` 글자를 더 줄인다.
