# 93. 인원 구성 TODO — 그룹별 인원수·개별 추가/삭제

작성: 2026-10-15. 상태: **미착수** (룰과 무관하게 진행 가능).

## 현재 동작 (`server/src/db/roster.ts`, `RosterCard.vue`)

- 관리자 화면 "인원 구성" 카드에서 **그룹 수 / 참가자 수 / 진행자 수** 세 숫자만 입력하고 "적용".
- 참가자 추가: 인원이 가장 적은 그룹에 한 명씩 배정. 이름 "참가자 N", 랜덤 PIN, 첫 로그인 때 본인이 이름 입력.
- 참가자 삭제: 수를 줄이면 **가장 나중에 만든 계정부터** 삭제. 특정 사람을 골라 지울 수 없음.
- 그룹 수 변경: 뒤 코드부터 삭제/추가하고 **전체 참가자를 다시 고르게 재배정** (13명·4그룹 → 4·3·3·3). 기존 배치가 섞임.
- 참가자 수만 바꿀 때는 기존 배치 유지, 추가분만 적은 그룹에 투입.
- 그룹당 리더 1명 보장 (기존 리더 유지, 없으면 id 최소 참가자).
- 진행자 최소 1명. 시드 관리자(ADMN)와 요청자 본인은 삭제 제외. 프레젠테이션 계정은 건드리지 않음.
- 화면에서 **특정 참가자를 다른 그룹으로 옮기거나, 한 명만 추가/삭제하는 기능 없음**. 개별 제외는 "계정 관리" 카드의 비활성화만 가능. 완전 삭제는 DB 직접 수정 (`DELETE FROM users WHERE id=?`).
- 그룹 이름은 "A 그룹"… 고정. 관리자 화면에서 이름 변경 기능 없음.

## 한계

- **그룹 간 인원은 항상 균등(차이 최대 1명)** 으로만 만들어진다. 방송처럼 그룹마다 인원이 다른 구성(예: 화이트 3명·블루 4명)을 만들 수 없다.
- 운영 중 한 명 추가·교체·그룹 이동이 필요하면 DB를 직접 만져야 한다.

## 선택지 (추천: 3)

1. **인원 구성 카드를 그룹별 입력으로 변경**
   - 그룹 수를 정하면 그룹마다 인원수 칸이 생김. 적용 시 그룹별로 그 수에 맞춰 계정 생성 / 뒤에서부터 삭제.
   - 자동 재배정 제거. 그룹이 없어질 때만 소속 참가자를 남은 그룹으로 이동(또는 삭제).
   - API: `POST /api/admin/roster` 입력을 `{ groups: [{ code, name?, participants }], staff }` 형태로 변경.
2. **계정 관리 카드에 개별 조정 추가**
   - 행마다 "그룹 이동" 드롭다운, "삭제" 버튼. 그룹 머리글에 "이 그룹에 1명 추가".
   - API: `POST /api/admin/users` (그룹 지정 생성), `DELETE /api/admin/users/:id`, `POST /api/admin/users/:id/group`.
   - 리더 삭제·이동 시 그룹당 리더 1명 규칙 재적용 필요.
   - 인원 구성 카드는 "처음 한 번 세팅"용으로 유지.
3. **1 + 2** — 초기 세팅은 그룹별 인원으로, 당일 변동은 개별 조정으로. 작업량 최대, 운영 편의 최대.

## 함께 결정할 것 (추천은 앞)

- 그룹 수를 줄일 때 소속 참가자: **남은 그룹으로 이동** / 삭제
- 그룹 이름: **관리자 화면에서 수정 가능하게** (방송처럼 화이트·블루·레드·블랙 등) / "A 그룹" 고정 유지
- 삭제된 계정의 과거 이벤트(`events.created_by`, `target_id`): **그대로 둠**(이름은 "삭제된 참가자"로 표시) / 함께 삭제
- 삭제 시 접속 중인 세션 처리: 비활성화와 동일하게 **refresh 토큰 폐기 + 소켓 끊기**
