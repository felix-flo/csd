# 99. 전쟁 — 선포·비용·승패·전리품 (+ 계정 관리 개별 PIN 보기)

> 작성일: 2026-10-23
> 상태: **구현 완료**. API e2e 35건(전쟁) + 기존 e2e 전체 통과, 브라우저로 리더 선포 → 강조 알림·전쟁 띠·거래 중지 → 관리자 승리팀 지정(확인 팝업) → 전리품(승리팀만) 확인.
> 관련: [95.게임진행_설계.md](95.게임진행_설계.md) (하루 흐름·거래), [97.보석골드_발행.md](97.보석골드_발행.md)

## 1. 요구사항 요약

- 거래 활동 단계에서 리더가 특정 팀을 골라 전쟁을 선포한다. 진행 중인 전쟁이 있으면 다른 팀은 선포할 수 없다.
- 선포 비용(보석·골드·크레딧)은 관리자가 일차마다 정하고, 정해야 다음 날로 넘어갈 수 있다. 낸 비용은 소멸한다.
- 선포되면 그때부터 어떤 거래도 할 수 없다. 모든 화면에 "⚔️ 전쟁이 선포되었습니다 (공격팀 → 방어팀)" 강조 알림.
- 관리자가 오프라인 게임 결과로 승리팀을 지정(확인 팝업). 승리팀은 상대 팀 모든 재화의 절반을 가져가고, 수량은 승리팀만 안다.

## 2. 결정 사항

| # | 항목 | 결정 |
|---|---|---|
| 1 | 선포 횟수 | 하루(일차)에 **게임 전체 1회**. 취소·무승부도 1회로 친다 |
| 2 | 선포 단계 | **거래 활동 단계만** |
| 3 | 권한 | **리더만** |
| 4 | 비용 재화 | 보석·골드·**크레딧**("티켓") |
| 5 | 비용 설정 | 1일차는 게임 설정(저장해야 시작 가능), 이후는 관리자가 N일차를 끝내기 전에 N+1일차 비용을 정해야 "다음 날로" 가능. 0 허용(무료), 마지막 날은 다음 날 비용 없음 |
| 6 | 거래 금지 범위 | **모든 팀**. 선포 순간 진행 중 거래는 자동 취소 |
| 7 | 거래 금지 기간 | **결과가 나올 때까지**. 결과 후 다시 거래 가능 |
| 8 | 선포 알림 | 전체(scope=all), 빨간 강조 팝업 + 소리. 전쟁 중에는 모든 화면 상단에 "⚔️ 전쟁 중: A → B · 결과가 나올 때까지 모든 거래 중지" 띠 |
| 9 | 결과 선택지 | 공격팀 승 / 방어팀 승 / **무승부 / 전쟁 취소**. 무승부·취소는 재화 이동 없음, 비용 반환 없음 |
| 10 | 전리품 | 패배팀 재화 **4종 모두 절반, 내림** (5 → 2). 0 이면 0 |
| 11 | 결과 공개 | 승리팀 이름은 전체에 ("… 승리했습니다 (공격 → 방어). 거래를 다시 시작합니다"), 오간 수량은 승리팀·**패배팀**(+관리자)에게 ("⚔️ 전쟁 패배: 보석 10, … 을 빼앗겼습니다", 2026-10-28 [100](100.최종룰_차이_결정사항.md) D6-a). 다른 팀은 승패만 |
| 11-b | 비용 공지 (D6-b) | 날이 시작될 때(게임 시작·다음 날로) 전체 알림 끝에 "⚔️ 오늘 전쟁 선포 비용: 크레딧 3" — 바뀌지 않아도 매일. 단계 전환 알림에는 없음 |
| 12 | 현황판 (2026-10-28, [100](100.최종룰_차이_결정사항.md) D5) | 프레젠테이션에 오늘 선포 비용 상시 표시 → 선포되면 "전쟁 중: 공격 → 방어" → 결과 후 "오늘 전쟁: … · 결과". `GameState.war.today = { attacker, defender, status }` (전리품 없음) |
| 13 | 미결 상태 | 결과가 나올 때까지 단계 넘기기·게임 종료를 막는다 |

## 3. 데이터 — `server/migrations/0010_war.sql`

| 테이블 | 용도 |
|---|---|
| `war_costs(day, gem, gold, credit)` | 일차별 선포 비용. 1일차는 게임 설정, 게임 시작·리셋 때 2일차 이후 삭제 |
| `wars` | day UNIQUE(하루 1회), attacker, defender, status(declared/attacker_won/defender_won/draw/cancelled), cost, spoils |
| `idx_wars_one_active` | 진행 중(declared) 1건 |
| `resource_ledger.reason` | `war_cost`(소멸), `war_loss`, `war_spoils` |

## 4. 동시성

1. **동시 선포**: day UNIQUE + 진행 중 1건 index. 늦은 쪽은 409 이고 비용 차감도 같은 트랜잭션에서 롤백.
2. **동시 결과 지정**: `UPDATE wars … WHERE id = ? AND status = 'declared'` changes 로 한 번만.
3. 거래 요청은 진행 중 전쟁이 있으면 409 `war_active`.

## 5. API

| 메서드 | 경로 | 역할 | 설명 |
|---|---|---|---|
| POST | `/api/war/declare` | 리더 | `{ defenderId }` 거래 활동 단계. 오류: `wrong_phase`, `not_leader`, `same_team`, `war_active`, `war_used`, `no_war_cost`, `insufficient` |
| POST | `/api/admin/war/cost` | admin | `{ gem, gold, credit }` 다음 날 비용 (마지막 날 409 `last_day`) |
| POST | `/api/admin/war/:id/resolve` | admin | `{ result: attacker\|defender\|draw\|cancel }` (`already_decided`) |
| PUT | `/api/admin/game/settings` | admin | `warCost?` 1일차 비용 |
| POST | `/api/admin/game/start` · `/next` · `/end` | admin | 1일차 비용 없음 → `no_war_cost`, 다음 날 비용 없음 → `no_war_cost`, 진행 중 전쟁 → `war_active` |

- `GameState.war = { active, usedToday, cost }` (모든 역할), `AdminGameView.war = { today, todayCost, nextCost }`.
- 이벤트(`type='game'`, payload.war = 강조 팝업): `war.declared`(all, 선포한 리더에게도 팝업), `war.resolved`(all), `war.spoils`(승리팀 group), `war.lost`(패배팀 group).

## 7. 계정 관리 개별 PIN 보기 (같은 작업에서 추가)

- 기존 "PIN 보기" → **"전체 PIN 보기 / 전체 PIN 숨기기"**.
- 각 계정 줄 PIN 옆 **"PIN 보기 / PIN 숨기기"** 로 그 계정만 표시. 전체 숨기기를 누르면 개별로 연 것도 닫힌다.
- 시작 전 "참가자 PIN" 카드는 배부용이라 전체 보기만 유지.
