# 99. 전쟁 — 선포·비용·승패·전리품 (+ 계정 관리 개별 PIN 보기)

> 작성일: 2026-10-23
> 상태: **구현 완료**. API e2e 35건(전쟁) + 기존 e2e 전체 통과, 브라우저로 리더 선포 → 강조 알림·전쟁 띠·거래 중지 → 관리자 승리팀 지정(확인 팝업) → 전리품(승리팀만) 확인.
> 관련: [95.게임진행_설계.md](95.게임진행_설계.md) (하루 흐름·거래), [97.보석골드_발행.md](97.보석골드_발행.md)
> 용어 (2026-10-28, [100.최종룰_차이_결정사항.md](100.최종룰_차이_결정사항.md) §5): 이 문서의 **"일차" = 화면의 "라운드"** (코드·DB·API 의 `day` 는 그대로). 단계 이름은 생산게임 · 거래 · 리더 협의로 바뀜.

## 1. 요구사항 요약

- 거래 활동 단계에서 리더가 특정 팀을 골라 전쟁을 선포한다. 진행 중인 전쟁이 있으면 다른 팀은 선포할 수 없다.
- 선포 비용(보석·골드·크레딧)은 관리자가 일차마다 정하고, 정해야 다음 날로 넘어갈 수 있다. 낸 비용은 소멸한다.
- 선포되면 그때부터 어떤 거래도 할 수 없다. 모든 화면에 "⚔️ 전쟁이 선포되었습니다 (공격팀 → 방어팀)" 강조 알림.
- 관리자가 오프라인 게임 결과로 승리팀을 지정(확인 팝업). 승리팀은 상대 팀 모든 재화의 절반을 가져가고, 수량은 승리팀만 안다.

## 4. 동시성

1. **동시 선포**: day UNIQUE + 진행 중 1건 index. 늦은 쪽은 409 이고 비용 차감도 같은 트랜잭션에서 롤백.
2. **동시 결과 지정**: `UPDATE wars … WHERE id = ? AND status = 'declared'` changes 로 한 번만.
3. 거래 요청은 진행 중 전쟁이 있으면 409 `war_active`.

## 5. API

| 메서드 | 경로 | 역할 | 설명 |
|---|---|---|---|

| POST | `/api/admin/war/:id/reject` | admin | `{ reason? }` 선포 거절 → 공격팀에만 알림, 라운드 1회 미포함 (§8) |

## 8. 선포 승인 (2026-10-29 결정·구현)

> 리더 협의에서 나온 "전쟁 금지/재개" 같은 운영진 안건을 관리자가 재량으로 반영할 수 있게, 선포 뒤 **관리자 승인/거절** 단계를 둔다. docs/100 N1-c(전쟁 금지 토글)는 이 기능으로 대체.

### 8-1. 결정

| # | 항목 | 결정 |
|---|---|---|
| 1 | 흐름 | 리더 선포 → **승인 대기(pending)** → 관리자 **승인**(declared, 지금의 전쟁 중) 또는 **거절**(rejected) |
| 2 | 대기 중 거래 | **새 거래 제안만 막음** (`war_pending`). 이미 진행 중인 거래는 계속되고, **승인되는 순간** 취소(지금 선포 때 하던 것을 승인으로 옮김). 거절되면 그대로 이어짐 |
| 3 | 비용 | 선포 때는 **보유량만 확인**, **승인될 때 차감**(소멸). 거절이면 재화 변동 없음. 승인 시점에 부족하면 승인 실패(대기 유지, 관리자가 거절하거나 정정) |
| 4 | 알림 | 대기: **공격팀**("진행자 승인 대기 중")과 **관리자**(승인/거절 요청)만. 승인: 지금처럼 전체 강조 공지. 거절: 공격팀에만, 사유(선택) 포함. 현황판·방어팀·다른 팀은 승인 전까지 모름 |
| 5 | 라운드당 1회 | **거절은 횟수에 넣지 않음**. 같은 라운드에 같은 팀·다른 팀이 다시 선포 가능 |
| 6 | 대기 중 진행 | 대기 중에도 단계 넘기기·게임 종료 **불가** (승인/거절을 먼저) |
| 7 | 거절 사유 | 관리자 입력란(선택). 비우면 "진행자가 거절했습니다" |

### 8-2. 변경 계획

**데이터** — `server/migrations/0015_war_approval.sql`
- `wars.status` CHECK 에 `pending`, `rejected` 추가 (SQLite 는 CHECK 변경이 안 되므로 테이블 재생성·복사), `reject_reason TEXT` 추가
- `wars.day UNIQUE` → 부분 유니크 `idx_wars_one_per_day ON wars(day) WHERE status != 'rejected'` (거절은 횟수 미포함)
- `idx_wars_one_active` → `WHERE status IN ('pending', 'declared')` (대기·진행 중 합쳐 1건)

**서버**
- `db/war.ts`
