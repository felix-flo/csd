## 1. 요구사항 (2026-10-16)

- 팀은 고정으로 예상. 기본 팀 종류: 화이트 · 옐로우 · 블루 · 레드
- 게임 시작 전 팀마다 팀원 수를 세팅한다. 팀당 최소 1명
- 팀 이름 앞에 팀 색을 표시해 참가자가 자기 팀 색을 바로 알 수 있게 한다
- 참가자 **삭제는 없다**. 탈락(비활성화)과 팀 이동만 가능하다. 탈락자는 팀 재화·알림을 받지 못한다
- 팀 테이블에 `team_color` 컬럼(RGB 값)을 두어 나중에 팀이 추가돼도 색을 지정할 수 있게 한다
- 팀 추가 시 간단한 팔레트에서 색을 골라 RGB 값을 저장한다

## 2. 결정 사항

| # | 항목 | 결정 |
|---|---|---|
| 1 | 팀 표시 이름 | 한글: 화이트 팀 / 옐로우 팀 / 블루 팀 / 레드 팀 |
| 2 | 기존 DB 그룹 처리 | A→화이트, B→옐로우, C→블루, D→레드 순서 매핑. 참가자 소속 유지. 5번째 이후 그룹은 삭제하고 소속 참가자는 인원 적은 팀으로 이동 |
| 3 | 팀 색 표시 형태 | 이름 앞 10px 원형 색 점 + 헤어라인 테두리. 화이트는 흰 점에 진한 테두리 |
| 4 | 인원 감소 입력 | 막는다. 입력란 최솟값 = 현재 인원, 서버도 거부. 빼는 것은 탈락 처리·팀 이동으로만 |
| 5 | 팀 관리 범위 | 추가 + 이름·색 수정 + **빈 팀(소속 0명) 삭제**. 기본 4팀도 수정·삭제 대상 |
| 6 | 탈락자 접속 | 로그인 차단 (현재 비활성화 동작 그대로). 별도 탈락 화면 없음 |
| 7 | 색 값 형식 | `#rrggbb` 소문자 hex. 팔레트 목록에 있는 값만 허용 |
| 8 | 리더 규칙 | 팀당 리더 1명 유지. 이동·탈락으로 리더가 빠지면 남은 활성 참가자 중 id 최소가 리더 |
| 9 | 팀 이동 시 세션 | ~~재로그인~~ → **재로그인 없음** (2026-10-16 변경). access token 에는 `sub`·`role` 만 두고 팀·리더 여부는 매 요청 DB 에서 읽는다. 접속 중인 소켓은 이전 팀 룸에서 새 팀 룸으로 옮긴다 |
| 10 | 팀 이동 알림 | 이전 팀·새 팀 팀원에게 "홍길동 님이 팀을 이동했습니다 (화이트 팀 → 블루 팀)" 를 각 1건. 룸을 먼저 옮기므로 이동한 본인은 새 팀 알림 1건만 받는다 (replay 도 현재 팀 기준) |

## 3. 변경 내용

### 3.1 DB — `server/migrations/0004_team_color.sql`

```sql
ALTER TABLE groups ADD COLUMN team_color TEXT NOT NULL DEFAULT '#888888';
-- 기존 a~d → 기본 4팀 (이름·색만 변경, id 와 소속 참가자 유지)
UPDATE groups SET code='white',  name='화이트 팀', team_color='#ffffff' WHERE code='a';
UPDATE groups SET code='yellow', name='옐로우 팀', team_color='#f5c518' WHERE code='b';
UPDATE groups SET code='blue',   name='블루 팀',   team_color='#006bff' WHERE code='c';
UPDATE groups SET code='red',    name='레드 팀',   team_color='#e5484d' WHERE code='d';
-- 5번째 이후 그룹 소속 참가자는 서버 기동 시 ensureTeams() 가 인원 적은 팀으로 옮긴 뒤 그룹을 삭제한다
```

- SQL 만으로는 "인원 적은 팀" 계산이 번거로워 5번째 이후 그룹 정리는 기동 시 코드(`ensureTeams()`)에서 한다.
- `ensureTeams()`: (1) `groups` 가 비어 있으면 기본 4팀 생성 (2) 코드가 `white/yellow/blue/red/t<n>` 형식이 아닌 그룹은 소속 참가자를 인원 적은 팀으로 옮기고 삭제. 멱등.
- 시드(`seed.ts`): `DEV_GROUPS` 를 기본 4팀으로, PIN 을 `WLDR/WMEM`, `YLDR/YMEM`, `BLDR/BMEM`, `RLDR/RMEM` 으로 변경. 기존 `ALDR` 등은 남아 있으면 그대로 둔다(멱등 시드).

### 3.3 서버 — 팀 API (`server/src/db/teams.ts` 신설, `routes/api.ts`)

| 메서드 | 경로 | 역할 | 동작 |
|---|---|---|---|
| GET | `/api/teams` | 모든 역할 | `{ teams: GroupInfo[] }`. 알림 피드·거래 화면에서 상대 팀 이름·색 표시용. 인원·재화는 포함하지 않음 |
| POST | `/api/admin/teams` | admin | `{ name, color }` → 팀 생성. code 는 `t5`, `t6`… 자동 (기존 최대 번호 + 1). 이름 중복 거부 |
| PATCH | `/api/admin/teams/:id` | admin | `{ name?, color? }` 수정 |
| DELETE | `/api/admin/teams/:id` | admin | 소속 참가자(활성·비활성 모두) 0명일 때만. 아니면 409 `team_not_empty` |

- `listGroups()` / `findGroupById()` 가 `team_color` 를 `color` 로 포함하도록 수정.
- 팀 변경(생성·수정·삭제)은 `system` 이벤트 `{ kind: 'teams.updated' }` 를 `scope=all` 로 보내 클라이언트가 팀 목록을 다시 받게 한다.

### 3.4 서버 — 인원 구성 (`server/src/db/roster.ts`)

```ts
interface RosterInput { teams: Record<number, number>; staff: number; keepAdminId: number }
// teams: { [teamId]: 목표 인원 } — 활성·비활성 포함 member 수
```

- 팀마다 `목표 - 현재` 만큼 생성 (이름 `참가자 N`, 랜덤 PIN, `name_set=0`). 음수면 400 `cannot_shrink`.
- zod: 팀당 `min(1).max(50)`, 존재하지 않는 teamId 거부, 요청에 없는 팀은 변경 없음.
- 제거: 그룹 생성·삭제, 균등 재배정(`rebalance(…, even=true)`).
- 유지: 진행자 최소 1명 / 시드 관리자·요청자 보호, 그룹 없는 참가자 배정, 팀당 리더 1명 보장.
- 진행자 수 감소도 요구사항 "삭제 없음" 에 맞춰 **막는다** (입력 최솟값 = 현재 진행자 수). 진행자를 빼야 하면 DB 직접 수정.

### 3.5 서버 — 팀 이동 (`POST /api/admin/users/:id/team { teamId }`)

- member 만 대상. 같은 팀이면 무시.
- 트랜잭션: `group_id` 변경 → 이동한 사람 `is_leader=0` → 원래 팀에 활성 리더가 없으면 활성 참가자 중 id 최소를 리더로 → 대상 팀에 리더가 없으면 이동한 사람을 리더로.
- (변경) 토큰 폐기·소켓 종료 없음. `moveUserRooms(userId, from, to)` 로 룸만 옮긴다.
- `system` 이벤트 `{ kind: 'member.moved', userId, userName, fromTeamId, fromTeamName, toTeamId, toTeamName, message }` 를 **두 팀**에 `scope=group` 으로 1건씩 발송. 응답 `{ users: AdminUser[] }`.

### 3.6 서버 — 탈락 처리

- 기존 `/api/admin/users/active` 그대로. 비활성화 = 로그인 거부 + refresh 폐기 + 소켓 종료 + `requireAuth` 거부 + `listGroupMembers` 제외. 재화·알림 수신 차단은 이것으로 충족.
- 추가: 비활성화된 사람이 리더였으면 같은 팀 활성 참가자 중 id 최소를 리더로 승계 (현재는 승계 없음).
- 비활성 대상 팀에 `system` 이벤트 `{ kind: 'member.eliminated', userId }` 를 `scope=group` 으로 발송해 팀원 목록을 갱신한다.
